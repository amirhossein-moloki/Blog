# راهنمای کامل تست و صحت‌سنجی سیستم بک‌آ‌پ و بازیابی فاجعه (BDR)
این سند راهنمای جامعی برای تست دستی و خودکار سیستم Backup & Disaster Recovery (BDR) در بستر محلی پروژه است.

---

## ۱. تنظیم متغیرهای محیطی مورد نیاز (Environment Variables)
سیستم بک‌آپ برای کارکرد صحیح در بستر رمزگذاری شده، نیاز به تنظیم متغیرهای محیطی خاصی دارد. قبل از شروع تست، دستورات زیر را در خط فرمان خود اجرا کنید تا متغیرها به صورت موقت در جلسه جاری شما تنظیم شوند:

```bash
# دایرکتوری پایه برای ذخیره بک‌آپ‌های ایجاد شده
export BACKUP_DIR="./my_test_backups"

# فعال‌سازی مکانیزم رمزگذاری AES-256-GCM
export BACKUP_ENCRYPT="true"

# کلید رمزگذاری بک‌آپ‌ها (یک عبارت امن دلخواه)
export BACKUP_ENCRYPTION_KEY="my_secure_super_secret_key"
```

---

## ۲. راهنمای تست دستی دستورات مدیریتی جنگو (Manual Commands Testing)

سیستم بک‌آپ دارای چهار دستور مدیریتی اصلی جنگو در مسیر `common/management/commands/` است:

### الف) تست بک‌آپ پایگاه داده (`backup_database`)
این دستور یک خروجی فشرده شده (Gzip) و رمزگذاری شده (AES-256-GCM) به صورت ایمن و مستقیم (بدون نشت داده خام بر روی دیسک) از پایگاه داده شما تهیه می‌کند.

```bash
# اجرای دستور به صورت پیش‌فرض
python manage.py backup_database

# در صورتی که می‌خواهید بک‌آپ در دایرکتوری دلخواه ذخیره شود و مکانیزم پاکسازی دوره‌ای اجرا نشود:
python manage.py backup_database --output-dir ./custom_db_backups --no-cleanup
```

**روش تأیید صحت خروجی:**
به مسیر دایرکتوری خروجی بک‌آپ بروید. شما باید فایل‌های زیر را مشاهده کنید:
- یک فایل بک‌آپ دیتابیس با پسوند `.sql.gz.enc`
- یک فایل مانیفست SRE با پسوند `_manifest.json` که متادیتای بک‌آپ، اندازه فایل و هش SHA-256 فایل را نگه می‌دارد.

---

### ب) تست بک‌آپ رسانه‌ها (`backup_media`)
این دستور فایل‌های دایرکتوری `MEDIA_ROOT` را به صورت جریانی و افزایشی با دایرکتوری مقصد همگام‌سازی می‌کند و از ویژگی محافظت در برابر حذف تصادفی (Deleted Object Protection) پشتیبانی می‌نماید.

```bash
# اجرای همگام‌سازی پیش‌فرض
python manage.py backup_media

# برای فعال کردن مقایسه دقیق‌تر با بررسی کامل هش SHA-256 فایل‌ها:
python manage.py backup_media --strict
```

**روش تأیید صحت خروجی:**
1. فایلی در مسیر رسانه‌ها ایجاد کنید و دستور را اجرا کنید تا آپدیت افزایشی انجام شود.
2. فایلی را در مسیر رسانه‌ها حذف کرده و دستور را مجدداً اجرا کنید. به خروجی کنسول دقت کنید که پیام محافظت شده `[PROTECTED]` را نمایش داده و فایل از بک‌آپ مقصد حذف نمی‌شود.

---

### ج) تست بک‌آپ کانفیگ‌ها (`backup_config`)
این دستور فایل‌های پیکربندی پروژه اعم از `.env` ،`docker-compose.yml` و تنظیمات Nginx را فشرده کرده و با الگوریتم AES-256-GCM رمزگذاری می‌کند.

```bash
python manage.py backup_config
```

---

### د) تست فرآیند بازیابی سیستم (`restore_system`)
این دستور فرآیند بازیابی ایمن و ۸ مرحله‌ای (Maintenance Mode، قطع اتصالات فعال دیتابیس، صحت‌سنجی سلامت و یکپارچگی فایل‌ها، پاکسازی Schema، مهاجرت داده‌ها و تست سلامت مجدد) را انجام می‌دهد.

```bash
# بازیابی کامل پایگاه داده تستی
python manage.py restore_system --db-file ./my_test_backups/database/db_backup_xxxx_xxxxxx.sql.gz.enc --decrypt

# بازیابی هم‌زمان دیتابیس، رسانه‌ها و فایل‌های پیکربندی
python manage.py restore_system \
  --db-file ./my_test_backups/database/db_backup_xxxx.sql.gz.enc \
  --media-file ./my_test_backups/media \
  --config-file ./my_test_backups/config/config_backup_xxxx.tar.gz.enc \
  --decrypt
```

*نکته مفید:* اگر این دستور را بدون هیچ آرگومانی اجرا کنید، سیستم به طور خودکار آخرین بک‌آپ‌های پوشه بک‌آپ را کشف کرده و یک فرآیند شبیه‌سازی شده بازیابی هفتگی (Dry Run) را برای تست سلامت فایل‌ها اجرا می‌کند:
```bash
python manage.py restore_system
```

## ۳. اجرای تست‌های خودکار دامنه‌ای (Automated Unit Testing)

پروژه دارای مجموعه‌ای غنی از ۲۹ تست‌ واحد خودکار برای کل سیستم بک‌آپ است که سناریوهای رمزگذاری اشتباه، فایل خراب، رفتار در صورت قطع بودن سرویس ردیس و تمیزکاری دوره‌ای GFS را با دقت پوشش می‌دهد. برای اجرای این تست‌ها در محیط مجازی `uv` دستور زیر را بزنید:

```bash
uv run python manage.py test common.tests.unit.test_bdr
```

این تست‌ها در محیط کاملاً ایزوله اجرا شده و در انتها باید پیام تایید موفقیت (`OK`) را در کنسول دریافت نمایید.
